# 盘物

一个把「慢慢盘，自有光」放在桌面的文玩陪伴应用。Electron 桌面挂件与盘玩手记共享本地存档，也可以在浏览器中预览界面。

## 启动

已经生成桌面应用时，双击项目内的 `启动盘物.command`，或直接打开 `dist/盘物-darwin-arm64/盘物.app`。这是本机开发构建，已做本机 ad-hoc 签名，尚未做 Apple Developer 身份签名、公证和安装包发布。

开发运行需要 Node.js 22.12 或更新版本：

```sh
npm install
npm start
```

`npm start` 同时打开盘玩手记和透明桌面挂件。拖动挂件的提示气泡可调整位置，物件区域用于手动盘玩；挂件可设为始终置顶。关闭手记窗口后挂件继续陪伴；菜单栏图标可以重新打开手记、隐藏挂件或退出整个应用。`⌘Q` 完全退出。

```sh
npm run dev     # 浏览器预览：http://127.0.0.1:4173
npm test        # 游戏规则与存档测试
npm run test:desktop # 使用临时存档验证原生双窗口、透明度、沙箱和共享状态锁
npm run test:ui  # 完整界面流程验证与截图
npm run build   # 打包当前系统、当前架构的桌面应用到 dist/
```

浏览器预览不具备透明窗口、系统置顶、菜单栏与原生桌面通知能力。浏览器与桌面应用各用自己的本地存档。

## 玩法与边界

- 打开应用后会自动盘玩免费基础物件，可以选择核桃、葫芦或文玩玉米，再切换盘玩方式和养护操作。
- 净手和棉手套采用后方手掌、物件、前景指腹与拇指的分层握持，并参照用户 GIF 分成四类：玉米、葫芦与玉件侧握揉擦；核桃在浅掌窝托滚；紫檀、黄花梨、金刚与紫金鼠在环内轻蜷四指、顶部拨珠；檀香、星月、椰蒂与橄榄核松握、顶部捻珠。掌根稳定，以拇指和接触物件的局部动作为主。主界面与挂件共用八张裸手/手套素材，各物件保留尺寸与位置微调；这是二维分层模拟，不是三维关节追踪。实物尺寸依据见 [握持与比例](docs/GRIP-SCALE.md)。
- 鼠标悬停物件时进入手动模式；移动鼠标才会揉搓、盘动或刷拭，静止悬停不会增长。移开鼠标后恢复自动陪伴；跨窗口共享手动控制，短暂控制租约可在窗口意外关闭后自动恢复。
- 不同材质有不同的清洁、干手、手套、湿度与温度偏好。环境参数由用户在应用内设置，是游戏模拟，应用不会读取温湿度传感器或判断用户真实手汗。
- 五阶段外观采用略夸张的材质染色、深度和反射光泽，便于清楚辨别进阶；手部和手套保持原色。玉石主要增强润光、椰蒂保持黑褐。
- 盘玩时间影响颜色、光泽与阶段。十二种物件分别使用按周、月、年设置的进阶曲线，每件物品的进度分别保存，达到阶段后可领取奖励。阶段切点是参考玩家观察制定的游戏数值，详见 [养护资料与时间尺度](docs/CARE-REFERENCES.md)，不代表实物必然达到同样效果；“传世”是游戏阶段名。
- 存档保存在本机，不上传云端。离线期间不累计盘玩进度；演示与外观预览加速会明确标示，预览可按每秒三十天观察长期变化。每日奖励要求真实陪伴时间十五分钟，预览加速不会提前发放每日奖励。
- 材质、养护效果和价格是游戏设定，不构成实物养护或市场价格承诺。

## 微信与支付宝

当前版本是**支付演示**：可以选择微信或支付宝并体验本地订单与商品解锁流程，**不会发起真实支付，不提供收款码，不会扣款**。请勿将演示订单当作交易凭证。客户端本地数据也不能作为真实商品权益的依据。

正式收款需要部署独立的可信后端，提供商户资质、签约权限和相应密钥/证书，并完成支付平台要求的上线配置。密钥不得放进 Electron 安装包、前端代码或本地存档。正式服务必须负责：

1. 根据服务器商品目录创建订单并确定金额，拒绝相信客户端传入的价格。
2. 微信 Native 支付向商户下单接口获取真实 `code_url`；支付宝调用交易预创建接口获取真实支付二维码。
3. 对支付平台异步通知验签，校验商户、订单号、金额与成功状态，必要时向平台查单。
4. 以幂等事务更新订单和账号权益，处理重试、超时关单、退款及权益回收。客户端只查询结果，不能自行宣布真实订单已支付。
5. 配置 HTTPS 回调域名、服务端持久化数据库和用户账号体系，再把当前演示结算替换为真实服务。

微信服务端通常需要已绑定的 AppID/商户号、商户证书序列号和私钥、APIv3 密钥，以及微信支付公钥与公钥 ID 或受支持的平台证书配置；通知须先验签再解密。支付宝服务端需要 AppID、应用私钥及支付宝公钥或证书模式配置，按所签约产品的要求接入。目前项目没有支付平台适配器、验签回调服务或远程账号权益系统。

官方接口说明：[微信支付 Native 下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)、[微信 Native 开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791891)、[支付宝交易预创建](https://developer.alibaba.com/docs/doc.htm?articleId=862&docType=4&treeId=180)。

## 实现

- `index.html`、`styles.css`、`app.js`：盘玩界面、商店、奖励和桌面挂件。
- `src/engine.js`：可独立测试的游戏状态与规则。
- `src/visuals.js`、`assets/items/`：十二种独立生成的写实透明文玩素材及其随阶段变化的外观。
- `docs/asset-prompts-extra.md`：进阶物件的外观参考来源与完整生成提示词。
- [握持与比例](docs/GRIP-SCALE.md)：实物尺寸来源与四类握姿的物件对应。八张参考素材的提示词分别见[侧握揉擦](docs/asset-prompts-reference-pinch.md)、[核桃托滚](docs/asset-prompts-reference-walnut.md)、[环内拨珠](docs/asset-prompts-reference-beads.md)、[松握捻珠](docs/asset-prompts-reference-loose.md)；GIF 逐格观察见 [参考动作分析](artifacts/reference/ANALYSIS.md)。
- `src/patina.js`：十二种材质各自的五阶段视觉参数。
- `docs/asset-prompts-interactions.md`：手掌、手套与刷具素材的生成记录。项目写实位图采用内置 imagegen 独立生成，保留透明背景，参考网页只用于材质与形态核对。
- `electron/main.cjs`、`electron/preload.cjs`：桌面窗口、菜单栏、通知和受限 IPC。
- `scripts/dev-server.mjs`：仅监听 `127.0.0.1` 的静态预览服务。

桌面窗口通过受限的 `panwu://app` 标准安全源加载界面，共享本地存档并通过 Web Locks 串行更新。窗口启用进程沙箱与上下文隔离，关闭渲染进程 Node.js 集成；预加载桥只暴露必要的窗口和通知方法。可参考 [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security/)、[Electron 自定义协议](https://www.electronjs.org/docs/latest/api/protocol)。
